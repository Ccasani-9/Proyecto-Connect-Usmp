# Base demo Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Preparar una base demostrable con acceso Google verificado, roles consistentes y calendario/reseñas sin errores conocidos.
**Architecture:** Conservar MVC e Identity. Verificar el ID token de Firebase con IdentityModel y certificados públicos de Google; obtener identidad solo del token validado. Mantener el diseño existente y proteger el contenido dinámico. SQLite y cuentas semilla siguen siendo parte de la maqueta.
**Tech Stack:** .NET 10, EF Core SQLite, Identity, Firebase cliente, IdentityModel, xUnit y pruebas HTTP.
**Spec:** Alcance aprobado en esta conversación: fix/base-demo, después del merge del PR #12 a develop.

## Global Constraints
- Rama fix/base-demo desde develop actualizado; PR hacia develop, sin merge automático.
- Conservar cuentas demo y la identidad visual guinda/Inter existente.
- No modificar el archivo no versionado ESPECIFICACION_PROYECTO_CODEX.md.
- No depender de credenciales privadas de Firebase para verificar firmas públicas.
- ResetOnStartup permanece disponible pero desactivado por defecto; activación explícita para demos desechables.

## Review Focus
- Un correo enviado sin token, un token vencido/de otro proyecto o con firma falsa nunca crea una sesión.
- Un usuario Google sin apellido puede publicar reseñas y consultar el detalle.
- Los roles de profesor existentes no se sustituyen ni amplían al iniciar sesión.
- Títulos/comentarios con HTML se muestran como texto; eliminar recordatorios incluye antiforgery.
- Dos arranques sin reset conservan los datos; el reset explícito solo se prueba sobre almacenamiento temporal.
